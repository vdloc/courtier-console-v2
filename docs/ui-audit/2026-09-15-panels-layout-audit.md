# UI/UX Audit — Northgate Plant Extension console (panels, layout, sizing, buttons, typography)

**Date**: 2026-09-15 · **Scope**: live dev server (`npm run dev`, :5176), master branch (uncommitted changes present in `Timeline.tsx`, `DiagramScene.tsx`, `StructureGlb.tsx`, `commands.ts`, `types.ts`, `viewSlice.ts` per `git status`)
**Method**: Playwright MCP — full-page screenshots at 375×812, 768×1024, 1280×800, and 1280×600 (short-laptop split-pane check); accessibility snapshot; `browser_evaluate` metrics script (font census, contrast, target size, off-grid spacing); Tab-order/focus probe; source cross-reference in `src/`.
**Standard**: WCAG 2.2 AA + `ui-ux-audit-playbook` thresholds.
**Relation to prior docs**: `docs/UI-AUDIT.md` (same date) flagged **UI-01** (left panel crushes viewport <475px) and **UI-02** (TopBar text overflow <420px) as P0/P1. Live-retest today shows **both are now fixed** — `App.module.css` has 900px/1200px drawer breakpoints for `.left`/`.right`, and `TopBar.module.css:71-84` truncates `.name`/`.revision` below 420px. Not re-scored below; see "Re-verified" section.

## Summary
Compact, information-dense 3-pane BIM console with an already-real design-token system (`src/design/tokens.css`) and a deliberate drawer-based responsive strategy (`App.module.css`, 900px/1200px breakpoints). The token discipline is good; the gaps are (a) a genuine split-pane starvation bug on short desktop viewports, (b) an orphaned interaction path (right drawer has no manual open control), (c) brand colors reused as small-text color without meeting contrast at the sizes actually shipped, and (d) a construction-timeline label collision on mobile. No dark/light theme toggle exists anywhere in the app.

**Critical 1 · High 4 · Medium 5 · Low 2**

## Systemic issues (root causes)
1. **Brand colors doing double duty as small-text color.** `--primary` (#1b75ec) and `--accent` (#da5515) are defined as *interactive/brand* colors in `tokens.css:14-17` but are also used as literal text/label color at 10-12px (`panels.module.css:53` `.link`, `panels.module.css:129-133` `.pick[data-active]`, `TopBar.module.css:39` `.export` bg + white text) — none of these meet 4.5:1 at the sizes shipped. One systemic fix (a darker `--primary-text` / `--accent-text` token for on-light small text) clears 6 of 9 measured contrast fails.
2. **Two independent scroll floors compete for one fixed-height column, with no minimum column height guaranteed.** `panels.module.css:38-42`'s `.controls { min-height: 120px }` comment literally documents the tradeoff ("one scroller collapses the tree to a row... keeps Layers/Display Mode/Tools reachable") — but at reduced viewport height, the *lower* floor loses too, dropping Tools/Measure/Isolate off-screen entirely (see CRIT-01).
3. **No manual-open affordance for the right drawer.** `TopBar.tsx` wires an explicit `IconButton icon="cube"` for the left explorer drawer but nothing symmetrical for the right (Measure/Properties) drawer — its `data-open` is derived only from `Boolean(selected) || measuring` (`App.tsx:29`). Fine on desktop (drawer is always docked ≥1200px) but on tablet/mobile it's an implicit, undiscoverable path.

## Quick wins (≤1 day)
- HIGH-01: introduce `--primary-text`/on-light darker variant, repoint `.link`/`.pick[data-active]`/`.phaseName`. (S)
- HIGH-02: hide/collapse timeline phase labels below a width breakpoint. (S)
- HIGH-03: add explicit right-drawer toggle button in `TopBar`. (S)
- MED-04/LOW-02: adjust tree row `aria-label`s. (S)

## Recommended tokens/components
- `--primary-text` / `--accent-text`: darker on-light variants of `--primary`/`--accent` for text/icon use at ≤13px, distinct from the brand fill colors (which are fine at their current values for solid buttons/borders/large elements).
- A shared `min-height` / `max-height` container query or `@media (max-height: …)` pattern for `.left`'s two internal scroll floors (CRIT-01) — currently two independent `min-height` floors with no coordination.
- Dark-mode token block under `[data-theme="dark"]` + `prefers-color-scheme`, if theming is in scope (MED-01).

## Open questions / needs verification
- Is touch input actually a target for the 900px/1200px breakpoint (tablet), or is it mouse-only at those widths with the drawer pattern purely for screen real estate? Answer determines whether HIGH-04 (target size) is Critical or can stay Medium/deferred.
- LOW-01 (focus ring visibility) should be re-checked in a real Chrome/Firefox window, not just computed-style — screenshot tooling may not be rendering `:focus-visible` outlines during automated capture.
- Theming (MED-01) may be intentionally out of scope for this build stage — confirm before treating as a gap to fix.
